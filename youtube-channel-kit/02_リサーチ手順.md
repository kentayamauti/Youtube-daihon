# リサーチ手順（全チャンネル共通）

結果は `channels/<チャンネル>/research/YYYY-MM-DD_<テーマ>.md` に置く。
最後に必ず「設計書のどこをどう直すか」を1〜3行で書く。

## 立ち上げ前リサーチ（この順で）

### A. お手本チャンネルの分析

1. お手本の直近20〜30本の再生数を取る
   ```
   python3 -I -c "import sys; sys.path.insert(0,'tools'); import yt, json; print(json.dumps(yt.channel('@お手本のハンドル'), ensure_ascii=False, indent=1))"
   ```
2. 1本ずつ「分類」をつけて `data/<お手本>_videos.csv`（公開日,タイトル,再生回数,分類）に入れる
3. 分類ごとの中央値と本数を出す → 「需要に対して供給が少ない分類」を探す
4. 伸びた回・伸びなかった回を2本ずつ選び、台本（原稿・字幕）を比べる
   比べる点：批評の相手／冒頭／独自の中身の割合／主張の数／締め
5. 投稿の間隔・同じ話題の続報の伸び方も見る

### B. 小規模チャンネル調査（需要の確認）

企画キーワードを `research/keywords_YYYY-MM-DD.txt` に1行1つ書いて回す。

```
python3 -I tools/small_channel_survey.py channels/<ch>/research/keywords_YYYY-MM-DD.txt channels/<ch>/research/YYYY-MM-DD_小規模チャンネル調査.md
```

- 条件（初期値）：今月公開／登録者1万人以下／再生が登録者の3倍以上／5,000回以上
- `--period week` で旬、`--max-subs 3000` でより厳しく
- 見方：当たりが多いキーワード＝小さいチャンネルでも需要がある。当たった動画のタイトルの型を企画に使う
- 1つのチャンネルだけが連発している場合は、そのチャンネルの固定ファンの可能性がある（割り引いて見る）

### C. 批判コメントの分類

1. お手本の伸びた回2本・伸びなかった回2本のコメントを読む（上位100件ずつ）
2. 批判／好意的に分け、批判は分類して数える（初期分類：叩く相手の偏り／中身が薄い／出所が怪しい／言い方が不快／サムネと中身が違う／やりすぎ）
3. レビューサイト・知恵袋でチャンネル名を検索し、同じ分類で数える
4. 結果を設計書「4. 良い動画の定義」の批判表に入れる

> コメントの取り方：クラウド環境（Claude Code on the web）からは YouTube の動画ページとコメントが止められる。
> 次のどれかで集める：①オーナーのPCのブラウザから Claude in Chrome で読む ②オーナーがコメントをコピーして貼る
> ③YouTube Data API のキーを環境に正しく設定する（`04_自動化の状況.md`）

### D. 良い動画の定義

- YouTube公式（ブログ・ヘルプ）の最新の方針を確認（満足度、収益化ポリシー、AI・量産の扱い）
- 設計書の5条件に変更が必要かだけ判断する

## 毎週のリサーチ（運用中）

1. B を「今週」で回す（新しい企画の種）
2. 自分のチャンネルの伸びた回・伸びなかった回を1本ずつ選び、台本採点のどこが違ったか書く
3. お手本の新着を見る（自分の企画と被っていないか。被ったら切り口を変える）
